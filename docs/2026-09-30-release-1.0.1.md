# Aura Quest 1.0.1, Build 5

Dieses Update enthält die vier Korrekturen aus dem Code Review, die bisher lokalen
Logo- und Store-Assets sowie das neue Editorial-Growth-Theme einschließlich seiner
lokalen Bilder, Schriften und Regressionstests.

## Korrigierte Abläufe

- Duelle erstellen, annehmen und ablehnen bleiben bis zum Ende der Anfrage aktiv,
  auch wenn das auslösende Widget verschwindet. Eine zweite Aktion während der
  laufenden Anfrage wird nicht zusätzlich gesendet. Antworten nach einem
  Kontowechsel aktualisieren keine Ansichten des neuen Kontos.
- Trophäen entfernen verwendet dieselben Schutzmaßnahmen und lädt danach die
  Trophäenliste neu.
- Ein erfolgreicher Statistik-Reset lädt Aktivitätsraster, Trophäen,
  Wochenrückblick und Check-in-Historien neu. Ein abgewiesener Reset verändert
  diese Anzeigen nicht. Auch neue Check-ins, synchronisierte Offline-Einträge
  und Fortschrittsänderungen aktualisieren das Aktivitätsraster.
- Einladungen, Freundschaftsanfragen und Freunde werden nach Wiederverbindung
  oder Fortsetzen der App neu geladen. Bei ausgefallenem Realtime-Socket läuft
  ein 45-Sekunden-Fallback ausschließlich im Vordergrund. Aufräumen beim
  Abmelden beendet Timer und Lebenszyklusbeobachter.

## Verifikation vor dem Push

- Flutter 3.44.6, Dart 3.12.2.
- `flutter analyze --no-pub`: keine Probleme.
- `flutter test --no-pub --reporter expanded`: 372 Tests bestanden.
- Darunter 18 neue Tests für die vier Korrekturen sowie die bestehenden Theme-,
  Responsive-, Reduced-Motion- und Golden-Tests.
- Android-Release-Manifest: `com.auraquest.aura_quest`, Version `1.0.1`,
  Versionscode `5`, Ziel-API `36`.
- Keine neue Datenbankmigration; keine Änderung am laufenden NAS-Stack.

Die Tests verwenden für die neuen Zustandsabläufe Repository-Fakes. Sie ersetzen
keinen weiteren End-to-End-Spieltest mit echten Konten auf einem Telefon.

## Store-Builds

GitHub Actions erstellt mit `build_number=5` beide Plattformen aus demselben
Commit. Android verwendet den bestehenden Release-Upload-Schlüssel. Ein neuer
Paketname oder ein neuer Schlüssel wäre für das vorhandene Play-Update ungeeignet
und wird deshalb nicht eingeführt.

Der iOS-Job erzeugt weiterhin ein unsigniertes Archiv zur Build-Prüfung. Der
Nutzer hat bestätigt, dass die Apple-Identitätsprüfung noch läuft. Eine
hochladbare App-Store-IPA setzt die aktivierte Mitgliedschaft und konfigurierte
Distributionssignierung voraus. iOS-Firebase/APNs und die weitere Apple-
Store-Freigabe sind ebenfalls offen; siehe den bisherigen Store-Readiness-Bericht.

Kopierfertige Versionshinweise und Upload-Schritte:
[RELEASE_NOTES_1.0.1.md](../../deploy/store/RELEASE_NOTES_1.0.1.md).
Die Release-Pipeline führt keinen automatischen Store-Upload aus.
